# Requirements Archive: BrewIndex v1.0 MVP

**Archived:** 2026-06-08 after v1.0 milestone completion
**Original Defined:** 2026-05-24
**Core Value:** A newcomer can discover, understand, and install any macOS app available via Homebrew without ever needing to know the CLI exists.

---

## v1 Requirements — Final Status

### Browse & Navigation

- [x] **BRWS-01**: User can browse all Homebrew casks in a visual card grid layout showing name, icon, and short description
  - *Outcome: Satisfied — Phase 2. CaskCard grid with icon/avatar, name, description, install pill.*
- [x] **BRWS-02**: User can filter casks by category (Developer Tools, Productivity, Design, etc.)
  - *Outcome: Partial — Phase 4. Category filter works for single-page results; does not persist across pagination (known gap accepted at v1.0 close).*
- [x] **BRWS-03**: User can sort the browse grid by popularity (install count), alphabetically, or most recently updated
  - *Outcome: Partial — Phase 4. Sort works within a page; sort state lost on page navigation (known gap accepted at v1.0 close).*
- [x] **BRWS-04**: User can paginate or infinitely scroll through 7,000+ casks without performance degradation
  - *Outcome: Partial — Phase 2. Pagination present; loses filter/sort state across pages (known gap accepted at v1.0 close).*

### Search

- [x] **SRCH-01**: User can search casks by name and get results from the database (server-side)
  - *Outcome: Satisfied — Phase 3. Postgres tsvector GIN search, debounced SearchInput, browse page search branch.*
- [ ] **SRCH-02**: User can filter search results by macOS platform compatibility
  - *Outcome: Deferred — no platform data in schema; requires Phase 1 backfill. Not scheduled for v2.*

### Detail Page

- [x] **DETL-01**: User can view a cask detail page with name, icon, description, version, and homepage link
  - *Outcome: Satisfied — Phase 2. Full hero page with all fields.*
- [x] **DETL-02**: User can copy the `brew install --cask <name>` command to clipboard in one click
  - *Outcome: Satisfied — Phase 2. CopyButton client island with 2s feedback.*
- [x] **DETL-03**: User can see current version and last updated date for a cask
  - *Outcome: Satisfied — Phase 2. Version + relative/absolute date in hero and metadata table.*
- [x] **DETL-04**: User can see 30-day, 90-day, and 365-day install counts for a cask
  - *Outcome: Satisfied — Phase 2. Three stat cards with formatted counts.*
- [x] **DETL-05**: User can see GitHub stars, forks, and open issues for casks that have an upstream GitHub repo
  - *Outcome: Satisfied — Phase 4. GitHubStatsCard + StarBadge, guarded by github_enriched.*

### Data Pipeline

- [x] **DATA-01**: Cask data is synced from the Homebrew JSON API daily via an automated cron job into Postgres
  - *Outcome: Satisfied — Phase 1 (Vercel Cron) + Phase 5 (Railway Cron). 7,659 casks synced daily.*
- [x] **DATA-02**: Cask icons are fetched from the homepage domain favicon at sync time and stored (not hotlinked)
  - *Outcome: Satisfied — Phase 1 (DuckDuckGo favicon) + Phase 5.1 (Tigris S3). Icons served from CDN.*
- [x] **DATA-03**: GitHub stats (stars, forks, issues, license) are enriched at sync time for casks with a GitHub upstream repo
  - *Outcome: Satisfied — Phase 1. Throttled Octokit, 1,083 casks enriched.*

### Security

- [ ] **SECU-01**: All API routes exposed to the public are protected by per-IP rate limiting (Upstash ratelimit)
  - *Outcome: Deferred — Upstash package in package.json; deferred per D-15. /api/search has Zod input validation.*
- [ ] **SECU-02**: Vercel WAF rules are configured to block known bot patterns and abusive traffic at the edge
  - *Outcome: Deferred — requires Vercel Enterprise plan. Not planned.*
- [x] **SECU-03**: The cron sync trigger endpoint is protected by CRON_SECRET bearer token validation
  - *Outcome: Satisfied — Phase 1. Auth guard is first statement in cron handler; Phase 5 Railway backend replicates.*
- [x] **SECU-04**: All server-side fetch calls are restricted to an explicit hostname allowlist (formulae.brew.sh, api.github.com, Blob storage) to prevent SSRF
  - *Outcome: Satisfied — Phase 1. fetch-allowlist.ts with full RFC 1918 block (21 entries). S3 SDK path acceptable.*
