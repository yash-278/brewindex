## Overview

BrewIndex v1.0 MVP delivers a complete App Store-like web UI for discovering Homebrew casks. Starting from zero, the milestone shipped a full data pipeline (sync, icons, GitHub enrichment), a polished dark-theme browse grid and detail pages, full-text search, category filters, sort controls, GitHub social proof, and a complete infrastructure migration to Railway hosting with Tigris S3 icon storage.

## Milestone Summary

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Casks only in v1 | Richer icons + more recognizable apps | ✓ Good — catalog is rich and recognizable |
| Next.js App Router full-stack | One repo, ISR for caching, easy Vercel deploy | ✓ Good — RSC + Server Actions pattern worked well |
| Sketch-first design | Validate visual direction before committing | ✓ Good — Raycast-inspired dark theme chosen, no design rework |
| Security as a constraint | Multi-layer protection chosen upfront | ✓ Good — SSRF, auth guard, ISR all working in prod |
| Railway migration | Move off Neon + Vercel Cron, reduce cost | ✓ Good — Railway $5/mo vs Neon + Vercel Pro |
| Tigris S3 for icons | No per-operation quota, co-located with backend | ✓ Good — icons loading from CDN reliably |
| AWS Nova Micro for categorization | ~200x cheaper than Claude Haiku for classification | ✓ Good — $0.14 total for 7,659 casks |

### Known Gaps at Close

- **BRWS-02, BRWS-03, BRWS-04 (Partial):** Pagination does not preserve filter/sort state. Category filter and sort dropdown work correctly for single-page results, but clicking to page 2 loses the filter/sort URL params. Root cause: Pagination component (Phase 2) was not updated when Phase 4 added filter/sort. Fix: update `src/components/pagination.tsx` to preserve `searchParams` when building page links.

- **Phase 5 not verified:** Railway Migration phase completed all 4 plans with SUMMARYs but was never formally verified with a VERIFICATION.md.

### Technical Debt Incurred

- `/api/search` route created in Phase 3 but unused — browse page uses direct `searchCasks()` query instead (architecturally correct; dead code)
- SSRF allowlist does not include Tigris hostname — S3 SDK bypasses safeFetch (acceptable, server-controlled)
- REQUIREMENTS.md checkboxes not updated after phases completed — documentation inconsistency resolved at milestone archival

### Deferred Requirements

- SRCH-02 (platform filter) — no platform data in schema; requires Phase 1 backfill
- SECU-01 (rate limiting) — Upstash package present; deferred per D-15
- SECU-02 (WAF rules) — requires Vercel Enterprise plan
