### Gaps Summary

**1 gap against ROADMAP Success Criteria SC #4:**

ROADMAP SC #4 states: "The SSRF allowlist (`fetch-allowlist.ts`) permits the Railway storage endpoint."

`fetch-allowlist.ts` has no Tigris hostname. However, the S3 upload path in `icons.ts` uses the AWS SDK's `S3Client.send()` — which makes its own HTTP connections — not `safeFetch`. The allowlist is never consulted for S3 writes. The DuckDuckGo favicon fetch still goes through `safeFetch` correctly.

**This looks intentional.** The S3 SDK manages its own connection pool and does not pass through the SSRF wrapper. Adding the Tigris endpoint to `ALLOWED_HOSTS` would be dead code. To accept this deviation, add to VERIFICATION.md frontmatter:

```yaml
overrides:
  - must_have: "The SSRF allowlist (fetch-allowlist.ts) permits the Railway storage endpoint"
    reason: "S3 SDK (PutObjectCommand) makes direct HTTP calls — it does not use safeFetch. Adding Tigris to ALLOWED_HOSTS would be unreachable dead code. The upload path is backend-only and server-controlled."
    accepted_by: "<your name>"
    accepted_at: "<ISO timestamp>"
```

Then re-run verification to close this gap.
