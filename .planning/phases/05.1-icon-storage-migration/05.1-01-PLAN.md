       - Create an `S3Client` singleton at module level (NOT inside the function — avoids per-call client instantiation).
       - `region` is hardcoded to the string `"auto"` — this is required by Tigris. Do not make it an env var.
       - `endpoint` comes from `process.env.S3_ENDPOINT!` (the Railway API endpoint, `https://t3.storageapi.dev`).
       - `forcePathStyle` MUST be `false` — Tigris uses virtual-hosted addressing. Setting it to `true` will route incorrectly.
       - Credentials come from `process.env.S3_ACCESS_KEY_ID!` and `process.env.S3_SECRET_ACCESS_KEY!`.
       - In `fetchAndStoreIcon`, after fetching the icon buffer:
           - `key` = `icons/${token}.ico`
           - `Bucket` = `process.env.S3_BUCKET!`
           - `Body` = `Buffer.from(iconBuffer)` (convert from ArrayBuffer to Node Buffer)
           - `ContentType` = `'image/x-icon'`
           - `ACL` = `'public-read'` — Tigris supports this canned ACL on PutObject
       - Construct the public URL as: `` `https://${process.env.S3_BUCKET!}.t3.storage.dev/${key}` ``
         NOTE: The API endpoint domain (`t3.storageapi.dev`) is separate from the CDN domain (`t3.storage.dev`). The URL stored in the DB MUST use `t3.storage.dev`. This is a known pitfall — see RESEARCH.md Pitfall 1.
       - The `allowOverwrite` option from `@vercel/blob` has no equivalent in S3 — S3 PutObject overwrites by default. Do not add any overwrite flag.
       - Preserve the `safeFetch` import and DuckDuckGo pitfall comment (line 21 in the original). The HTTP 200 check and fallback logic remain identical.
       - The function signature `fetchAndStoreIcon(token: string, homepage: string): Promise<{ url: string | null; isFallback: boolean }>` is unchanged.

       Final file shape:
       ```
       import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';
       import { safeFetch } from './fetch-allowlist';

       const DUCKDUCKGO_FAVICON = 'https://icons.duckduckgo.com/ip3';

       const s3 = new S3Client({
         region: 'auto',
         endpoint: process.env.S3_ENDPOINT!,
         credentials: {
           accessKeyId: process.env.S3_ACCESS_KEY_ID!,
           secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!,
         },
         forcePathStyle: false,
       });

       export async function fetchAndStoreIcon(
         token: string,
         homepage: string
       ): Promise<{ url: string | null; isFallback: boolean }> {
         let domain: string;
         try {
           domain = new URL(homepage).hostname;
         } catch {
           return { url: null, isFallback: true };
         }

         const faviconUrl = `${DUCKDUCKGO_FAVICON}/${domain}.ico`;
         const res = await safeFetch(faviconUrl);

         // PITFALL: DuckDuckGo returns a PNG body even on 404 — check HTTP status, NOT body length
         if (res.status !== 200) {
           return { url: null, isFallback: true };
         }

         const iconBuffer = await res.arrayBuffer();
         const key = `icons/${token}.ico`;
         const bucket = process.env.S3_BUCKET!;

         await s3.send(new PutObjectCommand({
           Bucket: bucket,
           Key: key,
           Body: Buffer.from(iconBuffer),
           ContentType: 'image/x-icon',
           ACL: 'public-read',
         }));

         const publicUrl = `https://${bucket}.t3.storage.dev/${key}`;
         return { url: publicUrl, isFallback: false };
       }
       ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend → Tigris API | S3 write credentials cross this boundary; must stay backend-only, never in browser bundle |
| Tigris CDN → next/image optimizer | Public icon URLs served from t3.storage.dev; next/image remotePatterns gates which hostnames are proxied |
| env vars → S3Client constructor | S3_ACCESS_KEY_ID and S3_SECRET_ACCESS_KEY must not appear in logs or error messages |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.1-01 | Information Disclosure | S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY env vars | mitigate | Credentials passed only to S3Client constructor in backend process; never logged, never included in error response bodies; env var validation checks key presence only (not value) |
| T-05.1-02 | Tampering | `icons/${token}.ico` S3 key construction | accept | `token` values are Homebrew cask tokens from the Homebrew API (validated alphanumeric identifiers); no user input reaches the Key parameter; path traversal not possible |
| T-05.1-03 | Elevation of Privilege | Bucket-level ACL vs object-level ACL | mitigate | Use object-level `ACL: 'public-read'` on PutObjectCommand; do not enable bucket-level public access; limits blast radius — only icon keys under `icons/` are public |
| T-05.1-04 | Spoofing | `S3_ENDPOINT` environment variable | accept | `S3_ENDPOINT` is server-side only; not user-controllable; no validation needed beyond correct Railway deploy configuration |
| T-05.1-05 | Information Disclosure | next/image remotePatterns wildcard | mitigate | Use exact hostname `roomy-breadbox-0sbir2el4w.t3.storage.dev` rather than `*.t3.storage.dev` to prevent next/image being used to proxy arbitrary Tigris buckets |
| T-05.1-SC | Tampering | npm install @aws-sdk/client-s3 | mitigate | Package legitimacy confirmed: official AWS SDK at github.com/aws/aws-sdk-js-v3, v3.1053.0, tens of millions of weekly downloads; slopcheck approved in RESEARCH.md Package Legitimacy Audit |
</threat_model>
