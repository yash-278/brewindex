## Deviations from Plan

### Auto-fixed Issues (Post-Checkpoint Fixes)

**1. [Rule 1 - Bug] Railway Tigris injects AWS_* env var names, not S3_***
- **Found during:** Task 4 checkpoint (post-deploy smoke test)
- **Issue:** The plan specified `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` but Railway's Tigris plugin injects credentials as `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`. The S3Client constructor was reading undefined credentials.
- **Fix:** Updated `src/lib/icons.ts` S3Client credentials to read `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`; updated env validation arrays in both sync routes to use the AWS_* names.
- **Commit:** fd19a7f

**2. [Rule 1 - Bug] Actual Tigris bucket CDN domain differs from plan specification**
- **Found during:** Task 4 checkpoint (post-deploy icon URL check)
- **Issue:** Plan specified CDN domain as `roomy-breadbox-0sbir2el4w.t3.storage.dev` but the actual Tigris CDN hostname from the Railway dashboard is `brewindex-icons.t3.tigrisfiles.io`.
- **Fix:** Updated `src/lib/icons.ts` `publicUrl` construction to use `brewindex-icons.t3.tigrisfiles.io`; updated `next.config.ts` `remotePatterns` to use the correct hostname.
- **Commit:** f5c4148

**3. [Rule 3 - Blocking] Vercel WAF was blocking ISR revalidation requests**
- **Found during:** Task 4 checkpoint (ISR revalidation smoke test)
- **Issue:** The Railway backend's POST to `/api/revalidate` was being blocked by Vercel's deployment protection, returning non-200. ISR cache was not being invalidated after sync.
- **Fix:** Added `x-vercel-protection-bypass` header with the protection bypass secret to the revalidation fetch call in the backend sync handler.
- **Commit:** e92510c
