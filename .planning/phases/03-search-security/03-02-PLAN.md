    Export async function GET(request: NextRequest):

      2. Parse with QuerySchema.safeParse({ q: raw.trim() })

      4. In a try block: const results = await searchCasks(parsed.data.q); return Response.json({ results })
      5. In catch: console.error('[api/search] error:', err); return Response.json({ error: 'Search failed' }, { status: 500 })

    The route returns { results: CaskSelectRow[] } on success, { results: [] } on invalid query, { error: string } on server error.

    Use Response.json() shorthand (not new Response + JSON.stringify) per shared patterns.
    No SSRF allowlist wrapper needed — this route queries Neon Postgres via Drizzle, not external HTTP.
    No rate limiting in this phase — per D-15, SECU-01 is deferred.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/search | Untrusted ?q string from browser; Zod validates before DB query |
| browse page → searchCasks | q from searchParams is server-side; Drizzle parameterizes before Postgres |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | /api/search ?q param | mitigate | Zod QuerySchema enforces min(2) max(100) before the value reaches searchCasks; Drizzle sql tag parameterizes ${q} as $1 in the prepared statement |
| T-03-05 | Denial of Service | /api/search amplification | mitigate | LIMIT 50 hard cap in searchCasks; GIN index ensures query time is O(log n) not O(n); empty query guard returns immediately without DB hit |
| T-03-06 | Spoofing | SSRF via /api/search | accept | Route makes no external HTTP fetches — only a Drizzle Postgres query; fetch-allowlist.ts is not invoked here |
| T-03-SC | Tampering | npm installs | accept | No new packages installed this phase; all dependencies already in package.json and verified clean |
</threat_model>
