# Phase 2 — UI Design Contract

> Visual and interaction contract for the Catalog UI phase. Covers /browse (card grid) and /cask/[token] (detail page). Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (pending `npx shadcn init` — executor initializes before first component) |
| Preset | none (manual token mapping below; run init with default dark preset and override with custom CSS vars) |
| Component library | Radix UI (via shadcn/ui) |

| Font (sans) | Geist Sans (already in layout.tsx via `next/font/google`) |

**Font note:** The sketch theme specified `-apple-system / JetBrains Mono`. The codebase already loads Geist Sans + Geist Mono via `next/font/google`. Use Geist — it is visually close to the sketch intent (clean, modern, developer-adjacent) and avoids an additional font load. Map `--font-sans` and `--font-mono` to Geist CSS variables already present in `layout.tsx`.

**shadcn init note:** `components.json` does not exist. Executor must run `npx shadcn init` (dark mode, CSS variables style) before importing any shadcn components. After init, override generated CSS variables in `globals.css` with the exact token values in the Color section below.

## Spacing Scale

All values are multiples of 4. Source: `sources/themes/default.css` (locked from sketch session).

| Token | Value | Usage |
|-------|-------|-------|
| space-1 | 4px | Inline padding on pills, gap between icon initials letter pair |
| space-2 | 8px | Gap between card header elements (name↔version), pill internal gap |
| space-4 | 16px | Card body gap, install-block padding, link-btn horizontal padding |
| space-6 | 24px | Page horizontal padding, hero element gap, hero content gap |
| space-8 | 32px | Page vertical padding, stats-meta flex gap |
| space-12 | 48px | Major section break (future use) |

Exceptions (sketch-locked values outside the standard 4-point scale — each carries a documented reason):
- Card metadata strip top margin: `4px` (space-1) — keeps strip flush below description
- Hero icon-to-body gap: `24px` (space-6)
- Header height: `56px` — not a spacing token; fixed component dimension
- Touch targets: minimum `44px` height on all interactive elements (Copy button, pagination buttons, link-btns)
- Sticky header `top`: `0px` in production (sketch used `44px` for variant nav; production has no variant nav)
- `12px` — grid gap between cards, install-block element gap, stat-card gap; tighter than 16px without going to 8px; preserves sketch card density
- `20px` — card padding, stat-card padding; preserves sketch visual rhythm between 16px and 24px
- `40px` — hero padding-top; preserves breathing room above hero without full 48px
- `2px` — Stat card flex-direction-column gap and pill vertical padding; sub-4px gap preserves compact chip/pill visual density; a 4px gap would over-space small inline elements
- `1px` — Inline `<code>` vertical padding; hairline top/bottom separation for inline code badges keeps them optically flush with surrounding text
- `5px` — Link-btn vertical padding and inline `<code>` horizontal padding; mid-step between 4px and 8px for button touch targets that must stay compact in the hero context
- `6px` — Breadcrumb separator horizontal margin (`margin: 0 6px`); visually balanced separator spacing between nav segments
- `7px` — Copy button vertical padding; 14px total vertical padding produces a visually balanced button height with 13px (0.8125rem) text

## Typography

Source: `sources/themes/default.css` + browse-grid.md + detail-page.md (all locked from sketch session).

**Scale:** 4 sizes only. **Weights:** 2 only (400 regular, 700 bold).

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Micro / section-label / mono-version | 11px (0.6875rem) | 400 | 1 | Geist Sans / Geist Mono | "INSTALL", "INSTALL STATS", "DETAILS" section labels (uppercase, `letter-spacing: 0.07em`); version badge and token label in cards (Geist Mono) |
| Label / UI / mono-install | 13px (0.8125rem) | 400 | 1.5 | Geist Sans / Geist Mono | Card description text, metadata values, pagination buttons, link-btns, copy button label; install command display (Geist Mono) |
| Body / card-name | 16px (1rem) | 400 (body) / 700 (name) | 1.5 (body) / 1.3 (name) | Geist Sans | Card descriptions (browse), hero description (weight 400); card name, hero links (weight 700) |
| Hero display | 32px (2rem) | 700 | 1.1 | Geist Sans | Cask name on detail page hero |

**Notes on collapsed entries:**
- Stat values previously at 20px now use 16px at weight 700 — the bold weight provides sufficient visual differentiation from body text at the same size.
- Section labels previously at weight 500 use weight 400 — uppercase + letter-spacing already creates visual hierarchy.
- Card names previously at weight 600 use weight 700 — bolder is cleaner at the collapsed scale.

**Rule:** Only Geist Sans and Geist Mono are used. No mixing with system fonts in production.

**Hero name tracking:** `letter-spacing: -0.03em`
**Stat value tracking:** `letter-spacing: -0.02em`
**Logo wordmark:** `font-weight: 700`, `letter-spacing: -0.02em`

### CaskCard (Browse Grid)

Structure (flex row, `align-items: flex-start`, `gap: 16px`):

1. **Icon slot** — `52px × 52px`, `border-radius: 10px`, `flex-shrink: 0`, `margin-top: 2px`
   - When `icon_is_fallback = false`: `<Image>` via `next/image` with `icon_url`, `width={52}`, `height={52}`, `alt="{name} icon"`, `placeholder="blur"` with generated blurDataURL

   - Hash algorithm for initials color: `djb2(token) % 6` → pick from 6 predefined muted-vivid colors (see Initials Color Palette below)

2. **Card body** — flex column, `gap: 8px`, `flex: 1`, `min-width: 0`
   - Header row: name (`font-size: 1rem`, `font-weight: 700`, `white-space: nowrap`, `overflow: hidden`, `text-overflow: ellipsis`) + version badge (`font-size: 0.6875rem`, `font-family: Geist Mono`, `color: var(--color-text-faint)`, `flex-shrink: 0`, right-aligned via `margin-left: auto` on a flex row)
   - Description: `font-size: 0.8125rem`, `color: var(--color-text-muted)`, `line-height: 1.5`, `-webkit-line-clamp: 2`, always visible (never hover-gated)

Hover: `border-color: rgba(124,106,255,0.4)`, `background: var(--color-surface-hover)`, `box-shadow: var(--shadow-glow)`. No `transform`. Transition: `all 0.15s ease`.

The entire card is a `<Link href="/cask/{token}">` — wrapped in Next.js `<Link>` for SPA navigation.

## Interaction Contracts

### Copy Install Command

Trigger: Click "Copy" button on `/cask/[token]`
1. Call `navigator.clipboard.writeText('brew install --cask ' + token)`
2. On success: change button text to "Copied!", change background to `#4ade80`, text color to `#0a0a0a`
3. After 2000ms: revert text to "Copy", revert background to `#7c6aff`
4. On clipboard API failure: change button text to "Failed", background to `var(--color-danger)`, revert after 2000ms
5. No toast, no modal — the button state change is the only feedback signal

### Card Navigation

Trigger: Click anywhere on a CaskCard in the browse grid
- The entire card is a Next.js `<Link href="/cask/{token}">` — SPA navigation, no full page reload
- No secondary click targets inside the card (homepage link is only on the detail page)

### Pagination

Trigger: Click "← Prev", "Next →", or a page number
- URL changes to `?page=N`
- Page is an ISR-cached Server Component — renders from CDN for cache hits
- No scroll-to-top behavior (browser default handles this)

### Search Bar (Phase 2 — non-functional)

The search bar renders with `disabled` attribute and `opacity: 0.55`. Clicking it does nothing. No tooltip or explanation — the visual treatment (grayed out) communicates its state.

## ISR and Data Contract

| Page | Revalidation | `generateStaticParams` | Cache Tag |
|------|-------------|----------------------|-----------|
| `/browse?page=1` (default) | `revalidateTag('casks')` | Pre-rendered at build | `casks` |
| `/browse?page=N` (all pages) | `revalidateTag('casks')` | Not pre-rendered; ISR on first request | `casks` |
| `/cask/[token]` (top 500) | `revalidateTag('casks')` | Pre-rendered at build via top-500 query | `casks` |
| `/cask/[token]` (remaining) | `revalidateTag('casks')` | Not pre-rendered; ISR on first request | `casks` |

All Postgres queries in Server Components must register with `fetch(..., { next: { tags: ['casks'] } })` or `unstable_cache(() => ..., [...], { tags: ['casks'] })`.

`generateStaticParams` for `/cask/[token]`: query `SELECT token FROM casks WHERE is_active = true ORDER BY install_365d DESC NULLS LAST LIMIT 500`.

Default sort for browse: `ORDER BY install_365d DESC NULLS LAST`.

All queries must filter `WHERE is_active = true`.
