<objective>
Replace the Neon HTTP database driver with the standard node-postgres driver and push the Drizzle schema to the freshly provisioned Railway Postgres instance.

Purpose: The @neondatabase/serverless driver only works correctly on serverless/edge runtimes via HTTP. Railway Postgres requires a standard TCP Postgres connection. This driver swap is the prerequisite for all other Phase 5 work — both the Next.js frontend and the Railway backend will import from src/db/index.ts after this change.

Output: src/db/index.ts using drizzle-orm/node-postgres with a pg.Pool (max:2, SSL-enabled); @neondatabase/serverless removed from package.json; Railway Postgres schema created via drizzle-kit push.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| .env.local → process.env | DATABASE_URL value transits from local env file to Node.js process; must not appear in client bundle |
| src/db/index.ts → pg.Pool → Railway Postgres | All DB traffic crosses TLS boundary; SSL required |
| Next.js server components → src/db/index.ts | DB client is server-only; must never be imported by client components |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | DATABASE_URL in Vercel env | mitigate | DATABASE_URL must be a server-only env var in Vercel dashboard (no NEXT_PUBLIC_ prefix); verify in Vercel project settings after cutover |
| T-05-02 | Tampering | pg.Pool SSL disabled in production | mitigate | ssl: { rejectUnauthorized: false } is set in Pool config conditioned on NODE_ENV === 'production'; connection without SSL on Railway will fail (Railway enforces SSL) |
| T-05-03 | Denial of Service | Connection pool exhaustion from Vercel cold starts | mitigate | max: 2 cap on pg.Pool limits connections per serverless instance; Railway Postgres default max_connections is ~100 which can absorb multiple warm instances |
| T-05-SC | Tampering | npm install after @neondatabase/serverless removal | mitigate | slopcheck approved all packages in research audit; no new packages installed in this plan; removal only |
</threat_model>
