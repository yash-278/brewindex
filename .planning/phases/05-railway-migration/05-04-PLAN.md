<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel cron removal | After this plan, the only sync trigger is Railway; no double-trigger risk |
| Railway service env vars | All secrets (DATABASE_URL, CRON_SECRET, GITHUB_TOKEN, BLOB_READ_WRITE_TOKEN) must be set as Railway service env vars, not in railway.toml (which is in git) |
| Railway backend public domain | The Railway-generated .railway.app domain is public; POST /sync is protected by CRON_SECRET; no other sensitive endpoints exist |
| Vercel redeployment | Updating DATABASE_URL in Vercel triggers a new deployment; old cached pages remain valid until revalidateTag fires |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-12 | Tampering | Double-trigger: Vercel cron AND Railway cron both live | mitigate | vercel.json crons array is removed in Task 1 before Railway is deployed; git commit includes the removal; double-trigger window is the gap between push and Vercel redeployment (< 5 min) |
| T-05-13 | Information Disclosure | Secrets in railway.toml (committed to git) | mitigate | railway.toml contains only startCommand and healthcheckPath; all secrets set via Railway dashboard env vars (never in railway.toml); enforced by acceptance criteria |
| T-05-14 | Information Disclosure | DATABASE_URL leaked to Vercel client bundle | mitigate | DATABASE_URL has no NEXT_PUBLIC_ prefix; Vercel treats it as server-only; verify in Vercel dashboard that the variable is NOT marked as "Exposed to Browser" |
| T-05-15 | Spoofing | Railway backend public URL accessed by unauthorized party | mitigate | POST /sync requires CRON_SECRET bearer token; GET /health is read-only and reveals only {"ok":true}; no sensitive data exposed via health endpoint |
| T-05-16 | Denial of Service | Railway hobby tier sleep behavior for cron trigger | accept | Cron trigger service sleeps between runs (Railway default); it wakes on the next scheduled run; 10-min wake-on-traffic delay applies to the trigger script execution; Railway docs confirm cron services wake correctly for scheduled runs even in sleep state |
| T-05-SC | Tampering | npm packages used in Railway deployment | accept | All packages already approved via slopcheck in RESEARCH.md; no new packages added in this plan |
</threat_model>
